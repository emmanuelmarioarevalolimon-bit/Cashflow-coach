PUBLICAR LA ENTREGA ORIGINAL EN CASHFLOW COACH

Repositorio de destino:
https://github.com/emmanuelmarioarevalolimon-bit/Cashflow-coach.git

1. Extrae TODO este paquete en una carpeta nueva.
2. Abre PUBLICAR.bat (doble clic, sin ejecutar como administrador).
3. Completa el inicio de sesion de GitHub si aparece.
4. Si Git no tiene nombre o correo para tus commits, el asistente los pide
   en tu equipo. Puedes usar el correo noreply mostrado en tu cuenta GitHub.
5. Revisa el destino y escribe SUBIR para publicar.

REQUISITOS
Windows PowerShell 5.1 y Git 2.28 o posterior (Git for Windows reciente).
Permiso de escritura en el repositorio. El asistente no cambia su visibilidad.
No cambia la politica permanente de PowerShell ni tu configuracion global Git.

VERSION CONSERVADA
6.0.0-web-integrada. c1-web-integrada.zip es el archivo original sin cambios.
SHA256:
3663b7eb7e2ee26af9547de4d66f4116778b7a720ea47b8396ffc67ea71bb3dc

El asistente crea una carpeta nueva, verifica el ZIP y todos sus archivos,
y comprueba que el commit contiene sus bytes originales. No ejecuta la app.
No copia tus carpetas actuales, .env, bases locales ni credenciales.
Los scripts de publicacion y este LEEME quedan fuera del repositorio de la app.

REPOSITORIO REMOTO
Sin ramas: publica en main.
Con alguna rama: crea entrega-web-final-6.0.0-FECHA-ID.
La segunda opcion es una instantanea con historial independiente, no un pull
request preparado para mezclar con main. En GitHub selecciona la rama indicada
para ver la app. No reemplaza main, no elimina ramas y no usa push --force.
Si el repo impone reglas que bloquean la subida, se detiene y muestra el error.

ESTADO
Este paquete prepara la publicacion. Crear o descargar el paquete NO publica
nada. La subida ocurre al ejecutar el asistente y confirmar SUBIR en tu equipo.
El comportamiento Git y la identidad de los archivos se comprobaron localmente;
el asistente PowerShell no se ejecuto en tu Windows ni se autentico a GitHub.
